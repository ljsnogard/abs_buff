# Demand 表示法重设计（起点 + 长度）后的审计与测试重写

日期：2026-09-30 21:54
涉及：`src/demand_.rs`（主体）、`src/slice_impl_.rs`、`src/buffer/segm_.rs`、
`tests/segm_async_io.rs`

> ⚠️ **本文 §2.9 与 §3 的 D10 / D11 已被
> [demand-20261001-0146.md](demand-20261001-0146.md) 取代**：`RangeBounds for Demand`
> 与 `Demand::as_ref` 均已删除，`T` 收紧为无符号整数，长度改用 `abs_diff` 的返回类型
> `DiffT<T>`，并新增 `Empty` 变体表达空集。D12 的结论保留。以下原文只作推演过程留档。

## 1. 新的表示与语义

`Demand` 不再直接存上下限，而是「起点 + 长度」，区间仍是左闭右开：

| 变体 | 取值集合 |
|---|---|
| `AtLeast(l)` | `{l, l + 1, ..., T::MAX}`（无上界） |
| `NoMoreThan(u)` | `{0, 1, ..., u}`，**上界含端点** |
| `BaseAndLen(b, l)` | `[b, b + l)`，不变量 `l >= 1`（空集一律用 `None`/`Err` 表达） |

`min()` / `max()` 给出**含端点**的约束边界（`None` = 该侧无约束）。由此：

* `exactly(usize::MAX)` 可精确表示（`max() == Some(MAX)`，内部是起点 MAX + 长度 1），
  不再需要 `MAX + 1` 这种无法表示的开区间上界——这正是重设计的动机；
* 搬移/读写实现可以直接把 `max()` 当作"最多搬多少"，上一轮为绕开 off-by-one 而引入的
  `demand_::max_count_`、`less_than(size + 1)`、`max - 1` 等补丁被**结构性消除**。

## 2. 审计发现的缺陷（本次均已修）

1. **`max()` 把开区间上界当含端点最大值**（`BaseAndLen(b, l) → b + l`）：消费者的
   "最多搬多少"因此多算一个（`exactly(n)` 会搬 n + 1），且 `exactly(MAX)` 直接上溢。
   改为 `b + (l - 1)`（先算 `l - 1` 再加 `b`，避免 `b + l` 上溢）。
2. **`len()` 对 `NoMoreThan(u)` 少一个**（`u` → `u + 1`）：`{0, ..., u}` 含 `u + 1` 个取值，
   改成饱和加法。
3. **`len()` 对 `AtLeast(l)` 少一个**（`MAX - l` → `(MAX - l) + 1`）：修掉旧实现把单点集合
   `at_least(MAX)` 算成 0 的问题。
4. **`compromise`：`AtLeast ∩ BaseAndLen` 长度算错并无符号下溢**
   （旧式 `min(c - a, d)`：`a > c` 时 `c - a` 下溢 panic，`a <= c` 时少算）。
   改为：`a <= c` 直接取右侧；否则先判 `a - c < d`，长度取 `d - (a - c)`。
5. **`compromise`：`NoMoreThan ∩ BaseAndLen` 少一个**（`min(b - c, d)` → 长度应含端点，
   `min((b - c) + 1, d)`）。旧写法在 `c == b` 时会构造出长度 0 的空区间，违反
   "空集用 `None` 表达"的不变量。
6. **`compromise`：`AtLeast ∩ NoMoreThan` 上溢**（`b - a + 1` 在 `a == 0 && b == MAX` 时
   `MAX + 1`）→ 改为复用 `between`（它会把唯一无法表示的全集退化为"无上界"）。
7. **`try_from_usize_range` 把开区间上界直接喂给含端点的 `between`**（`5..10` 多出一个取值），
   且 `Unbounded` 用 `T::MAX` 充数（`0..` 于是 `MAX + 1` 上溢 panic）。
   改为把上界换算成"含端点的最大取值"：`Included(v) → v`、`Excluded(v) → v - 1`、
   `Unbounded → None`（映射为 `AtLeast`）；`Excluded(0)` 这类空集返回 `Err`。
8. **`between` 的退化条件过宽**（`hi == T::MAX` → 无上界）：`between(MAX, MAX)` 会被表示成
   `AtLeast(MAX)`，同一个集合 `{MAX}` 却给出 `max() == None`。收窄到唯一会溢出的
   `lo == 0 && hi == MAX`。
9. **`RangeBounds::end_bound` 对 `NoMoreThan` 少一个**（`Excluded(u)` → `Included(u)`）。
   `BaseAndLen` 分支无法精确表达，见 §3（该 impl 现已被整体删除，见新文档）。

顺带修好的：`exactly` / `between` 的 doctest 断言（原本 `a.max().is_some(usize::MAX)` 无法编译、
`between` 的示例错写成断言 `b` 而非 `c`），以及 `len_without_is_empty` 的 allow。

## 3. 未决（需决策）

> D10 / D11 已在新文档中结案（删 impl、删 `as_ref`）；D12 保留。以下保留原始选项推演。

* **D10（已解决 → 删除该 impl）`RangeBounds for Demand` 在 `BaseAndLen` 上无法精确表达**：
  `end_bound` 必须返回
  `Bound<&T>`，而 `[b, b + len)` 的开区间上界 `b + len` 既没有存成字段，也可能是
  `T::MAX + 1` 无法表示。当前实现对它返回 `Excluded(len)`（错误值，已在源码注释里标注）。
  三条路：(a) 去掉该 impl；(b) `Demand` 额外缓存上界（引入冗余状态，表示法不再是纯
  「起点 + 长度」）；(c) 保留现状并降级文档。测试目前只断言可精确表达的
  `AtLeast`/`NoMoreThan`。
* **D11（已解决 → 删除 `as_ref`）`as_ref()` 产出的 `Demand<&T>` 已无访问器可用**：
  `min`/`max` 移进
  `T: funty::Integral` 的实现后，`Demand<&T>` 拿不到 `min`/`max`/`len`，该 `pub const fn`
  实际成了死接口。要么删掉，要么把不需要算术的 `min` 放宽到 `T: Copy` 的实现里。
* **D12（保留）「集合视角」与「约束视角」并存**：`at_least(usize::MAX)` 是单点集合
  （`len() == 1`）但没有上界**约束**（`max() == None`）。两处文档都已写明；若想统一
  （例如让 `AtLeast` 的 `max()` 返回 `Some(MAX)`）需要再决策。

## 4. `compromise` 的代码形态（评审后调整）

初版把 `{a, ...} ∩ [c, c + d)` 抽成了私有函数 `intersect_at_least_base_`，并在
`AtLeast ∩ NoMoreThan` 分支里复用 `Demand::between(a, b)`。评审意见是：分支里已经掌握了
全部约束，再套一层计算只是增加审阅难度。该意见成立，已按下述方式改回就地计算：

* 同一个"case 分析"只写一份，靠 **or-pattern** 让两种参数顺序共用一个分支
  （`(AtLeast(a), BaseAndLen(c, d)) | (BaseAndLen(c, d), AtLeast(a))`），因此不再需要
  抽函数来避免重复；
* 不再调用 `between`：该分支的 guard 已经保证 `a <= b`，`between` 的交换/规范化是空转，
  而且它自己的 `{0, ..., MAX}` 退化规则还得让读者再去核对一遍；
* case 分析写成一段连续的 `if / else if / else`，而**不是**用 guard：`a - c` 这个减法只在
  `a > c` 时安全，若改成两个带 guard 的分支，这个安全性就依赖于"前一个 guard 恰好失败"，
  属于隐藏的前后依赖。

真正无法省掉的是数量本身的运算：`a > c` 时交集是 `[a, c + d)`，长度只能写成
`d - (a - c)` —— 写成 `(c + d) - a` 会溢出（`Demand::between(1, usize::MAX)` 是合法需求，
其 `c + d == 1 + MAX`），写成 `c - a` 会下溢。测试表里专门加了两行
（`{2, ...} ∩ {1..=MAX}`、`{MAX, ...} ∩ {1..=MAX}`）盯住这一点。

遗留的一点重复：`{0, ..., MAX}` 的表示规则在 `between` 与该分支各出现一次（各一行，互相
注明）。若要去掉，可选 (a) 抽一个 `from_inclusive_(lo, hi)` 供两处使用（即评审中不喜欢的
那种小函数），或 (b) 把 `{0, ..., MAX}` 表示成 `NoMoreThan(MAX)`（精确、无需算长度，但会
让该集合的 `max()` 从 `None` 变成 `Some(MAX)`，属 §3 的 D12 决策）。

`try_from_usize_range` 仍调用 `between(l, u)`：该处没有 match 上下文，输入是任意
`RangeBounds`，`between(l, u)` 正好就是"`[l, u]` 对应的需求"的定义，不属于空转。
