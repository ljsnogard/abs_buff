# Demand 类型域收紧（无符号 + `DiffT`）与空集语义

日期：2026-10-01 01:46
涉及：`src/demand_.rs`（主体）、`src/lib.rs`、`src/slice_impl_.rs`、`src/buffer/segm_.rs`、
`tests/segm_async_io.rs`

本文取代 [demand-20260930-2154.md](demand-20260930-2154.md) 的 §2.9、§3（D10 / D11）；
D12 的结论保留。

## 1. 起因

上一轮把 `Demand` 改成「起点 + 长度」后仍有两类遗留：

1. 长度字段仍是 `T`，`Demand<T>` 对 `T` 也没有约束，于是 `as_ref()` 产出的 `Demand<&T>`
   没有任何可用访问器（D11），`RangeBounds::end_bound` 对 `BaseAndLen` 无法表达
   `b + len`（D10），`exactly(MAX)` / `between(0, MAX)` 只能靠「`MAX + 1` 装不下」
   这一偶然性来特判；
2. 「一个取值」与「两个取值的差」在类型上不可区分，`min` / `max` / `len` / `compromise`
   里到处是 `T` 与长度的混算。

本轮把长度抽成 **`abs_diff` 的返回类型**，并把 `T` 限定为无符号整数。

## 2. 决策与因果链

### D-A：类型域收紧为无符号（`T: Unsigned + Integral<Unsigned = T>`）

事实依据（funty 3.0.0-rc2）：`Integral::abs_diff(self, rhs) -> Self::Unsigned`；除此之外
该 trait **没有任何跨类型算术或泛型转换**（只有 `TryFrom<i8..usize>` 这类具体类型的实现，
以及同型的 `checked_*` / `saturating_*`）。于是 `max()` 里的 `b + (len - 1)`
（`T` + `DiffT<T>`）必须有跨域通道，可选：

* 加 `T: TryFrom<DiffT<T>>`：有符号且区间长度超过 `T::MAX` 时转换失败——例如
  `between(i32::MIN, i32::MAX - 1)` 的 `len - 1 == 4294967294` 转不回 `i32`，而真值
  `i32::MAX - 1` 明明可表示，`max()` 只能误报 `None`；
* 位重解释（`to_ne_bytes` / `from_ne_bytes`）：有符号也完整，但可读性很差；
* 收紧到无符号：关联类型等式让 `DiffT<T>` **归一化**为 `T`，全篇算术同型，`max()` 一句
  `checked_add` 写完。

`Demand` 的语义（隐式下界 0、`no_more_than` / `less_than`、计数）本来就以非负为前提；
有符号还会让「`T::MIN` 当隐式 0」「`..0` 判空」等一堆判断失效。因此选第三条：编译期排除
有符号（`Demand<i32>` 不再可实例化），仓库与下游都只实例化 `Demand<usize>`。

### D-B：公开 `DiffT`

```rust
pub type DiffT<T> = <T as Integral>::Unsigned;
```

从 crate 根逐项导出（`pub use demand_::{Demand, DiffT};`）。别名不带 where 子句也能通过
（对 `T` 的投影不要求别名自身声明边界），因此没有 `type_alias_bounds` 警告。

### D-C：`len()` 只在 `DiffT<T>: Into<usize>` 时提供

`len()` 单独放在一个 impl 块里，边界为 `DiffT<T>: Into<usize>`，返回 `DiffT<T>`。

⚠️ **已知边界**：std 只有 `impl From<u8/u16/…> for usize`，**没有** `From<u32> for usize`，
所以按此规则 `Demand<u32>::len()` 不存在（`u8` / `u16` / `usize` 有）。当前全仓库只
实例化 `Demand<usize>`，不受影响；若日后要放宽到 `u32`，改用
`usize: TryFrom<DiffT<T>>` 或自定义 trait 即可。

### D-D / D-E：删除 `as_ref()` 与 `impl RangeBounds for Demand`

`&T` 不满足 `Integral`（D11），`as_ref` 已是死接口，删除；`RangeBounds::end_bound` 必须
返回 `Bound<&T>`，而 `[b, b + len)` 的开区间上界既没存成字段、也可能是 `MAX + 1`（D10），
直接删掉该 impl（仓库内与下游都没有使用点）。

### D-F：`is_empty()` 的唯一解释是「取值集合为空」

旧实现的 `is_empty()` 对 `no_more_than(0)` 返回 `true`，但 `no_more_than(0)` 的取值集合是
`{0}`（`len() == 1`，测试早有断言）——同一个类型上两个查询互相矛盾。本轮明确：空集是一个
**合法的、一等的**取值集合，`is_empty()` ⇔ `len() == 0`，为此在 `DemandRange` 里新增
`Empty` 变体（而不是拿「长度为 0 的 `BaseAndLen`」充数）：

* `BaseAndLen` 的 `len >= 1` 不变量得以严格成立，`max()` / `compromise` 里所有 `l == 0`
  的特判都消失了；
* 空集的 `min()` 也如实返回 `None`（旧哨兵会返回 `Some(0)`，与「至少 0 个」同形）。

### H1 / I1：空集求交返回 `None`；消费侧尊重空集

`∅ ∩ X = ∅`。旧实现会把 `less_than(0) ∩ no_more_than(n)` 表达成 `BaseAndLen(b, 0)`，
消费侧据此取 `max()` 得到 `None`，于是：

* `segm_ref_output_async_` / `segm_mut_input_async_` 会在 `unreachable!()` 处 **panic**；
* `segm_ref_move_items_into_output_async_` / `segm_mut_move_items_from_input_async_` 把
  `(min, max) == (None, None)` 按 `unwrap_or(1)` + `unwrap_or(MAX)` 解释成
  「至少 1 个、无上界」，**无视需求把数据搬走**；
* `&[T]` / `&mut [T]` 的六个 `try_read` / `try_write` / `read_async` / `write_async` 会把
  空需求当成「至少 0 个、无上界」而借出整段。

处理：`compromise` 首臂直接 `(Empty, _) | (_, Empty) => None`；上述消费点显式
`demand.is_empty()` 判空（前两处返回 0，六个切片实现报 `Empty(Closing)`）。

## 3. 新的表示与不变量

| 变体 | 取值集合 |
|---|---|
| `Empty` | `∅`（仅 `less_than(0)` 构造） |
| `AtLeast(l)` | `{l, ..., T::MAX}`（无上界） |
| `NoMoreThan(u)` | `{0, ..., u}`，上界含端点 |
| `BaseAndLen(b, l)` | `[b, b + l)`，不变量 `l >= 1` |

* `between` 只在 `hi.abs_diff(lo) < T::MAX` 时构造 `BaseAndLen`，否则退化为
  `AtLeast(lo)`——只有全体取值 `{0, ..., MAX}` 会走到（长度 `MAX + 1` 装不进差值域；
  D12：该集合的 `max()` 是 `None`、`len()` 饱和）。
* 访问器：`min()` / `max()` 给含端点边界（空集与无约束侧都是 `None`）；`len()` 在差值域上
  计数、超出即饱和（`at_least(0)`、`no_more_than(MAX)`、全体取值都饱和到 `T::MAX`）。

## 4. 验证

* `cargo test`：26（lib）+ 8（集成）+ 9（文档）全绿；`cargo clippy --all-targets` 无告警。
* 新增用例：`full_range_degenerates_without_overflow`（全区间退化 / 参数顺序无关）、
  `less_than_matches_the_value_sets`（`less_than` 此前 0 覆盖）、`is_empty_agrees_with_len`
  （`is_empty` ⇔ `len == 0`）、`compromise_with_empty_is_none`（H1）、
  `empty_demand_is_rejected_by_borrowed_slice`（I1，切片侧）、
  `empty_demand_moves_nothing`（I1，两个聚合 provided method + 真实文件设备）。
  `is_empty_agrees_with_len` 里的 `len() == 0` 是 `clippy::len_zero` 的合理例外（改成
  `is_empty()` 会让断言变成同义反复），已加注释并 `#[allow]`。
* **7 组变异全部被捕获**（各自改回缺陷版本后 `cargo test` 失败）：`between` 丢全区间退化；
  `len(NoMoreThan)` 少加 1；`max(BaseAndLen)` 退化成直接取字段；`is_empty` 恒为假；
  切片消费侧去掉判空；聚合 provided method 去掉判空；`less_than(0)` 不再构造空集。
  变异均按字节还原（`cmp` 校验）。
